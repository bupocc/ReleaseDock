# ReleaseDock · 软件版本发布中心

一个可以在单台云服务器上用 Docker 部署的软件发布网站。管理员通过通行密钥管理项目、上传安装包和发布版本，支持在 Bitwarden 官方自托管密码库中保存凭据；访客无需登录即可浏览公开项目、阅读更新日志和下载已发布文件。

## 已实现

- 更新动态首页、最近更新项目轮播、项目目录搜索与分类、历史版本及手机端布局。
- WebAuthn 通行密钥登录、一次性初始化与恢复、备用凭据管理、HttpOnly 会话、登录限流和退出。
- 项目创建与编辑、图标上传、桌面及移动平台、官网地址、公开或隐藏。
- 灵活版本号、稳定版与预发布版、各状态版本信息编辑、Markdown 预览及最新稳定版标记。
- 安装包选择或拖入后自动上传，各状态附件均可改名、调整平台与架构、增删及替换内容。
- 普通页与后台页面地址只显示根路径，公开版本使用项目和版本路径，可直接访问和分享。
- 可使用键盘的自定义下拉框、项目支持平台标签、无需输入密码的登录页。
- 公开下载、文件大小、SHA-256 校验值、HTTP Range 断点续传。
- 后台概览、版本与文件列表、站点名称、简介和公告配置。
- SQLite 持久化、审计记录、Docker 健康检查及可选 Caddy HTTPS。

默认是空站点。`design/` 的项目和统计只用于设计图，不会写入正式数据库。

首页展示所有项目的最新发布动态；通过导航「全部项目」进入可搜索的项目目录。公开项目、版本和下载均无需登录。

## 页面与操作

首页保留站点公告与发布动态，公告和标题分区显示。「全部项目」顶部轮播最近更新的真实公开项目，每个项目只出现一次，展示最新已发布版本、项目介绍、日志纯文本摘要、支持平台及版本下载入口。尚无版本的公开项目显示待发布状态；只有一个项目时隐藏轮播控件，空站点不生成示例内容。

轮播每 6 秒切换一次，可通过前后按钮、指示点或左右方向键切换，Home / End 键可跳到首尾。鼠标悬停、焦点停留在轮播内或页面进入后台时暂停，临时暂停条件解除后重新等待 6 秒。手动暂停需点击继续；系统开启「减少动态效果」时关闭自动轮播和切换动画，仍可手动查看。

登录页使用「使用通行密钥登录」按钮，通过浏览器调用 Bitwarden 扩展或其他认证器；取消、超时后可重试。站点设置支持添加、改名和删除通行密钥，最后一把不能删除，删除当前凭据后会退出。修改凭据前如超过 5 分钟未验证，需要再次使用通行密钥确认。项目、渠道、平台、架构等选择项使用自定义下拉框，支持方向键、Enter / 空格确认、Escape 关闭。项目支持平台采用可勾选标签，支持 Tab 聚焦与空格切换。

内置平台为 Windows、macOS、Linux、Android、iOS、鸿蒙及 Web。项目配置、安装包下拉框、目录和下载列表使用同一套平台名称与图标。APK、AAB、APKS、XAPK 识别为 Android，IPA 为 iOS，HAP、HSP 为鸿蒙；未指定架构的移动安装包默认「通用」，可手动调整。已有自定义平台会继续保留。

普通页面及后台页面打开后，地址栏统一显示 `/`；当前页面信息随浏览器历史记录保存，刷新、前进和后退均可恢复。复制根地址到另一个标签页会打开首页。原来的 `?page=...` 链接仍可访问，并在打开后收起参数。

公开版本地址采用 `/<项目标识>/<实际版本号>`，例如 `/deskbox/v1.5.1`，分享按钮复制当前版本的完整地址。路径保留填写的版本号：填写 `1.5.1` 时路径为 `/deskbox/1.5.1`，填写 `v1.5.1` 时为 `/deskbox/v1.5.1`，两者共存时有各自独立地址。修改版本号后使用新地址；旧地址、下架版本和隐藏项目不再提供公开内容，也不会回退到其他版本。

## 本地启动

需要 Node.js 24 或更新版本，以及 pnpm。

```sh
pnpm install --frozen-lockfile
pnpm start
```

打开 `http://localhost:8080`。在另一个终端运行 `pnpm passkey:setup`，然后在本机打开 `.data/passkey-setup-link.txt` 中的一次性链接，创建首把管理员通行密钥。链接有效期为 15 分钟，成功绑定后立即失效；重新运行命令会使之前的链接失效。命令只输出保存位置，不回显链接令牌。

`127.0.0.1` 仍可浏览公开页面，但登录会引导到 `localhost`。通行密钥绑定域名，不能把 IP 地址与 localhost 混用。

## Docker 启动

需要 Docker Engine 和 Compose 插件。

```sh
docker compose up -d --build
docker compose ps
```

默认监听本机 `127.0.0.1:8080`，数据库、安装包、图标和通行密钥公钥保存在 `releasedock_data` 命名卷中。首次初始化：

```sh
mkdir -p .data
docker compose exec app node server/passkey-cli.js setup
docker compose cp app:/app/data/passkey-setup-link.txt .data/passkey-setup-link.txt
```

在装有并已解锁 Bitwarden 扩展的浏览器中打开文件里的链接。Windows PowerShell 可使用 `New-Item -ItemType Directory -Force .data` 创建目录。不要把注册链接放进公开文档、截图或仓库。

## 使用 Bitwarden 官方自托管密码库

1. 在 Bitwarden 浏览器扩展登录界面选择自托管服务器，填写你自己的 Bitwarden 服务地址并登录、解锁密码库。
2. 启用扩展的通行密钥保存与使用功能；具体选项名称可能随扩展版本变化。
3. 首次打开 ReleaseDock 的一次性注册链接，点击创建通行密钥，在 Bitwarden 弹窗中确认保存。
4. 后续点击「使用通行密钥登录」，在 Bitwarden 中选择已保存的凭据完成验证。

ReleaseDock 使用标准 WebAuthn，不连接 Bitwarden 密码库 API，不需要 Bitwarden API Token，也不接收主密码或私钥。Bitwarden 服务域名和 ReleaseDock 域名可以不同。凭据保存到哪个密码库由扩展控制，站点不能强制限定某个 Bitwarden 实例。推荐再添加另一台设备或硬件安全密钥作为独立备用。

### 全部凭据丢失时恢复

在服务器运行 `pnpm passkey:recover`；Docker 中运行 `docker compose exec app node server/passkey-cli.js recovery`，然后复制 `/app/data/passkey-recovery-link.txt` 到本机并打开。恢复链接同样只在 15 分钟内有效。新凭据成功验证前保留旧凭据；成功后在同一事务中撤销全部旧凭据、会话和待验证请求。项目、版本和安装包不受影响。

升级到此版本后，原文本密钥登录接口关闭，`ADMIN_KEY`、`ADMIN_KEY_FILE` 和旧密钥文件不再生效，旧会话一次性撤销。保留原数据卷，执行一次初始化即可。数据库会自动迁移，升级前应保留数据备份。更换 ReleaseDock 的正式域名需要在新域名重新绑定，可通过服务器恢复流程完成。

## 云服务器与 HTTPS

1. 将代码放到服务器，安装 Docker，给域名添加指向服务器的 DNS 记录。
2. 将 `.env.example` 复制为 `.env`，设置 `DOMAIN=releases.example.com`，固定正式域名后再绑定管理员通行密钥。
3. 在云防火墙放行 80/TCP、443/TCP；需要 HTTP/3 时放行 443/UDP。
4. 启动应用和 HTTPS 反向代理：

```sh
docker compose -f compose.yaml -f compose.https.yaml up -d --build
docker compose -f compose.yaml -f compose.https.yaml ps
```

随后访问 `https://你的域名`。Caddy 自动申请及续期证书，应用自动启用 Secure Cookie。再执行上面的 Docker 初始化步骤，生成的链接使用配置的正式 HTTPS 域名。

已有 Nginx、Caddy 或负载均衡器时，只启动基础 Compose，将请求反向代理到服务器的 `127.0.0.1:8080`，并设置 `.env` 中的 `COOKIE_SECURE=true`、`PUBLIC_URL=https://你的域名`、`TRUST_PROXY=1`。仅在确有可信反向代理时设置 `TRUST_PROXY=1`。

公网管理必须使用 HTTPS 域名。仅使用 HTTP 局域网 IP 无法注册或使用通行密钥；远程访问请先配置域名与 HTTPS。

网络无法访问 Docker Hub 时，可选择镜像源构建，不需要修改系统 Docker 设置：

```sh
docker compose build --build-arg NODE_IMAGE=docker.m.daocloud.io/library/node:24-bookworm-slim --build-arg NPM_REGISTRY=https://registry.npmmirror.com
docker compose up -d --no-build
```

## 常用配置

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `PORT` | `8080` | 本地端口或 Compose 映射端口 |
| `HOST` | `127.0.0.1` | 本地服务监听地址；容器内固定为 `0.0.0.0` |
| `DATA_DIR` | `.data` | 本地数据目录；容器中固定为 `/app/data` |
| `MAX_UPLOAD_MB` | `2048` | 每个安装包大小上限；项目图标上限为 2 MB |
| `SESSION_HOURS` | `12` | 会话有效期，最多 168 小时 |
| `COOKIE_SECURE` | 本地 `false` | HTTPS 源地址会强制启用 Secure Cookie |
| `PUBLIC_URL` | 本地 `http://localhost:PORT` | 正式环境须填写固定 HTTPS 域名源地址，不含路径、参数或账号 |
| `DOMAIN` | 空 | 使用 HTTPS Compose 时填写域名，不含协议 |

服务器根据配置确定 WebAuthn 来源和 RP ID，不信任客户端提交的 Host 或 Origin 来设置认证域名。注册与登录均要求用户验证；挑战限时、绑定浏览器且只能使用一次。

## 发布规则

1. 先创建项目，填写名称、标识和支持平台。
2. 创建版本，填写版本号、标题及更新日志，独立选择稳定版或预发布渠道。
3. 选择或拖入安装包后自动上传。新版本会先保存草稿；版本号、标题未完整时，文件保留在当前页面的队列中，补齐后继续上传。失败的文件可单独重试。
4. 检查平台、架构与发布预览，然后正式发布。

版本号支持 `1.5.0.1`、`nightly` 等数字版本或标签，长度为 1–100 个字符，以英文字母或数字开头，其余可使用英文字母、数字及 `. _ + -`；同一项目内不能重复。版本号不再限定为三段语义版本，后缀也不会自动决定发布渠道。

草稿及其附件不会公开。项目隐藏后，即使知道已发布文件的地址也无法下载。下架会立即关闭新发起的公开下载，已经开始的传输可能继续完成。

草稿、已发布和已下架版本均可编辑版本号、标题、更新日志与渠道。保存已发布版本时，原发布时间、发布状态、附件 ID 和文件内容保持不变，更新日志不能清空；保存下架版本也不会自动重新公开。发布和下架仍是独立操作。

草稿、已发布及已下架版本都可新增、删除、改名、调整平台与架构或替换安装包。附件操作即时保存，版本状态不变；修改已发布版本的附件后，访客会获取更新后的文件。下架或隐藏的附件仍不可匿名下载。删除全部附件后，已发布版本仍展示更新日志；重新发布仍须至少有一个安装包。

同一项目最多标记一个最新稳定版，只有已发布的稳定渠道版本可持有该标记。发布稳定版时可以指定；项目还没有最新稳定版时，新发布的稳定版会自动成为最新。编辑已发布稳定版时也可以交接标记。取消原最新标记、将其改为预发布或下架后，系统回退到其他已发布稳定版中发布时间最近的一项，没有候选则留空。轮播中的「最近发布」按实际发布时间选择，可能展示较新的预发布版，与此标记独立。

下载统计表示开始下载的请求数，不代表独立用户数。HEAD 请求和后续断点续传片段不会重复累计；从第一个字节重新发起下载会再次计数。

## 更新日志格式

后台编辑预览、发布预览和公开版本详情使用同一套 Markdown 解析。支持标题、引用及嵌套引用、链接、列表、粗体和斜体、行内代码、代码块及表格，例如：

```markdown
## 本次更新
> 升级前请备份配置。
> 阅读 [升级说明](https://example.com/guide)。

- 修复下载问题。
- 支持 `--version` 查看版本。
```

链接使用 `[文字](地址)`，地址包含括号时可写成 `[文档](https://example.com/release_(stable))`。需要原样显示语法时使用行内代码或反斜线转义。

原始 HTML 按文字显示，图片保留替代文字。链接只允许 HTTP、HTTPS、邮件及站内地址；外站链接在新标签页打开。解析器和 HTML 清理器由本站提供，无需访问外部 CDN。

目录轮播只显示经过清理的纯文本摘要，不显示 Markdown 格式标记或 HTML 标签，并略去完整代码块。完整日志仍以版本详情和预览中的内容为准。

## 修改安装包

选择文件后会自动上传；因版本信息未完整或文件名校验失败而等待时，可在队列中编辑完整名称。修改上传名称不会修改电脑上的原文件。

上传后，在版本编辑页直接编辑文件名，点击「保存名称」或按 Enter 保存，也可取消。保存成功后，列表、发布预览和浏览器下载文件名同步更新，不会丢失版本表单中尚未保存的编辑。后台「文件管理」仍使用重命名弹窗。

名称最多 180 个字符，支持中文。同一版本不能存在同名文件，名称不能包含路径、控制字符、Windows 非法字符或保留名称；也不能以空白开头、结尾或以句点结尾。

重命名及平台、架构修改保留原下载链接、文件内容和 SHA-256。通过「替换文件」上传新内容时，原文件保留到新文件完整上传成功，随后更新大小及 SHA-256，下载链接保持不变。失败时保留原文件；上传期间若另一操作已修改此附件，会拒绝覆盖并提示重新加载。

## 数据备份与更新

数据库、安装包、图标及凭据公钥位于同一个持久卷。私钥由 Bitwarden 或认证设备保存。更新容器不需要删除该卷：

```sh
docker compose up -d --build
```

下面的备份命令适用于云服务器上的 Bash。停服后对整个数据卷做一致性备份：

```sh
umask 077
mkdir -p backups
docker compose stop app
docker compose run --rm --no-deps -T --entrypoint tar app -czf - -C /app/data . > backups/releasedock-data.tar.gz
docker compose start app
```

备份包含会话及可能尚未过期的初始化票据，请作为私密文件保存。还原时先停止应用，将归档还原到空的数据卷，再启动；不要在服务运行时覆盖 SQLite 文件。不要执行 `docker compose down -v`，它会删除数据卷。

本地验收可在更新前运行 `node scripts/check-container.mjs capture`：读取业务记录、计算真实安装包及图标的 SHA-256，并在卷内生成 SQLite 一致性备份。更新后运行 `node scripts/check-container.mjs verify`，核对记录、文件、健康状态及容器前端内容。此脚本不依赖管理员登录、不重建容器，也不创建测试项目。

当前适合单实例部署。要运行多个应用副本，应先迁移到共享数据库与对象存储；不能让多个容器同时管理本地附件目录。

## 验证与设计产物

```sh
pnpm test
pnpm test:ui
pnpm preview:design
```

接口测试使用隔离临时目录，覆盖通行密钥真实签名、初始化、恢复、来源与重放保护、凭据管理和旧数据库迁移，以及项目、版本、上传、附件修改与替换、失败回滚、下载、范围请求、公开版本路径、下架和重启持久化。`pnpm test:ui` 依次运行 `scripts/check-ui.mjs`、`scripts/check-carousel.mjs`、`scripts/check-routing.mjs` 与 `scripts/check-passkeys.mjs`，使用 Playwright 和 Chrome 虚拟认证器验证原生 WebAuthn 及实际发布流程；测试数据不写入正式站点。浏览器脚本默认使用本地 Codex 运行时的 Playwright 和 Chrome，可通过 `DESIGN_NODE_MODULES`、`DESIGN_BROWSER` 指定安装路径。通行密钥专项截图保存在系统临时目录，可通过 `PASSKEY_PROOF_DIR` 调整。

浏览器自动化验证标准 WebAuthn，不代表已登录并验收某个真实 Bitwarden 自托管实例。首次生产绑定需由管理员在自己的 Bitwarden 扩展中确认。

- `design/previews/`：9 个页面的设计图片及手机长图。
- `design/preview.html`：可直接打开的单文件设计预览。
- `design/gallery.html`：设计图片画廊。
- `docs/技术方案.md`：技术取舍、权限与数据模型。
- `docs/验收记录.md`：本次实现的验证范围和结果。

设计图使用真实 HTML/CSS 页面渲染，便于从视觉稿延续到当前应用。
