# 软件发布中心技术方案

## 目标与边界

面向单个团队或个人自托管的软件发布需求。访客可以读取公开项目与已发布版本，下载软件；管理员用一个高强度密钥登录，管理站点、项目和版本。不引入用户注册、多租户或独立微服务。

## 技术选择

| 层次 | 本次选择 | 原因 |
| --- | --- | --- |
| 前端 | 原生 JavaScript 模块、HTML、CSS | 直接沿用已确认的页面，依赖少，构建和部署简单 |
| 更新日志 | Marked、DOMPurify | 后台和公开页共用 Markdown 解析，限制 HTML 标签及链接协议；依赖文件由本站提供 |
| 后端 | Node.js 24、Fastify 5 | 服务端会话、输入校验、流式文件上传与下载 |
| 数据库 | Node 原生 SQLite 驱动、WAL | 单机运维简单，项目与发布管理的写入规模较小 |
| 文件存储 | Docker 持久卷 | 安装包不放进数据库，更新容器不丢失文件 |
| HTTPS | 可选 Caddy 反向代理 | 自动证书申请与续期 |
| 部署 | Docker Compose | 将应用和数据目录分开，提供健康检查 |

替代方案是 Vue/React 配合独立 API 和 PostgreSQL，适合多人开发、更复杂的管理功能或多实例运行；目前会增加构建与运维成本。当前前端采用模块化组织，将来可以逐页替换。

## 公开页面与表单交互

`/` 与 `?page=home` 默认显示更新动态，`?page=activity` 保留为同内容入口；`?page=catalog` 独立提供项目目录、搜索、分类和排序。页面渲染、数据加载和事件绑定使用同一路由分工，目录事件只在目录页面绑定。动态首页采用紧凑的标题区、独立公告区和时间线，登录页简化右侧表单并保留隐藏标签、错误关联及页外返回入口。

目录通过一次 `GET /api/projects` 请求获得公开项目和各项目的 `latestRelease`。该字段为最新已发布版本的 ID、版本号、标题、日志片段、渠道和发布时间，另有 `notesTruncated` 标志；日志片段最多 1000 个字符，无已发布版本时为 `null`。版本按发布时间取最新，草稿与下架记录不进入摘要，不依赖全站最近 100 次发布记录去重。`latestVersion` 保留项目默认版本的含义，可能与最新一次发布的 `latestRelease.version` 不同。

`project-carousel.js` 按项目 ID 去重，以最新发布的时间排序；尚无版本的项目使用项目更新时间，并显示待发布状态。轮播展示介绍、平台、版本与详情下载链接，日志先经过 Markdown 解析和 HTML 清理，再提取纯文本并截取最多 220 字的摘要；完整代码块留在详情页。

轮播每 6 秒推进一项，普通模式使用 520 毫秒的位移与透明度过渡。悬停、组件内焦点、后台页面及手动暂停会停止计时，临时暂停条件解除后重新等待 6 秒；系统 `prefers-reduced-motion` 开启时关闭自动播放与切换动画。前后按钮、指示点、左右方向键及 Home / End 均可切换。非活动项设置 `inert` 与 `aria-hidden`，手动切换通过状态区域播报；0 或 1 项不展示播放控件。

`select-control.js` 将单选下拉增强为带 `combobox` / `listbox` 语义的控件，保留原生字段作为提交值来源，并同步禁用状态、校验信息和 `input` / `change` 事件。支持方向键、Home / End、Enter / 空格、Escape 及输入前缀定位。菜单独立挂载以避免被文件列表裁剪，按视口选择展开方向。项目支持平台以标签式复选框呈现，继续使用原生复选框的键盘与表单语义。

## 数据实体

- `projects`：名称、唯一标识、介绍、官网、平台、图标、可见性。
- `releases`：所属项目、唯一版本号、标题、更新日志、渠道、发布状态及时间。
- `assets`：所属版本、展示文件名、随机存储名、平台、架构、大小、SHA-256 与下载数。
- `sessions`：会话令牌摘要、CSRF 令牌与有效期。
- `settings`：站点信息，以及不会返回前端的内部设置。
- `daily_downloads`：按 UTC 日期汇总的下载开始次数。
- `audit_log`：登录、项目修改、上传、发布与下架等动作，不保存管理密钥。

数据库通过唯一约束保护项目标识、项目内版本号与文件名。同一个项目最多标记一个最新稳定版。

版本号是 1–100 个字符的标识，以 ASCII 字母或数字开头，后续仅允许 ASCII 字母、数字和 `. _ + -`，支持 `1.5.0.1`、`nightly` 等值，不要求三段语义版本。渠道独立使用 `stable` / `prerelease`，不从版本号后缀推断；版本展示和动态顺序依据发布记录，不能把版本标签当作可直接比较的语义版本。

## 权限规则

公开可读条件为 `项目公开 AND 版本已发布`。文件下载、版本详情和列表分别执行同一条件，避免只隐藏按钮却仍能通过 URL 访问。

管理接口的鉴权基于路由器实际匹配的路由模板，防止百分号编码改变原始 URL 后绕过前缀判断。写操作另校验 CSRF 令牌和请求来源。登录失败会限流，登录后使用 HttpOnly、SameSite=Strict Cookie；HTTPS 部署启用 Secure 属性。

原始密钥不存入浏览器；服务端使用 scrypt 比较密钥。会话令牌只在数据库保存摘要。密钥更换后，已有会话统一失效。

## 版本与附件一致性

`PATCH /api/admin/releases/:id` 允许草稿、已发布和已下架版本修改版本号、标题、日志及渠道；同项目版本号唯一约束仍覆盖所有状态。已发布版本的日志不能为空。保存只更新元数据与更新时间，保留原发布状态、发布时间、版本 ID 和附件内容。发布及重新发布使用独立发布接口，下架使用独立下架接口；编辑下架版本不会恢复公开访问。

最新稳定标记仅对已发布且渠道为 `stable` 的版本有效。同一事务内交接 `is_latest`，并由唯一索引约束每个项目最多一个。发布稳定版时可指定为最新；尚无最新标记时，新发布的稳定版自动成为最新。编辑时可把另一个已发布稳定版设为最新。取消当前最新标记、将当前最新改为预发布或将其下架时，优先回退到其他已发布稳定版中发布时间最近的一项；没有候选则留空。草稿与下架版本不能通过保存元数据取得有效最新标记。

安装包先流式写入临时文件并计算校验值，完成后原子重命名，再登记数据库。超限、中断或数据库冲突会清理此次上传产生的文件。正式发布前检查文件存在；附件提交时在事务内复核版本仍为草稿及附件数量上限。

安装包的增删、平台与架构调整只允许草稿执行。已发布和已下架版本不允许覆盖或替换文件；软件二进制内容需要修订时应创建新版本。版本号可以作为元数据更正，但同一附件 ID 对应的文件内容、大小与 SHA-256 不变。下架保留记录和文件，并关闭公开访问。

附件重命名使用 `PATCH /api/admin/assets/:id`，可单独提交 `filename`。事务内校验文件名及同版本唯一性，并更新版本时间、记录审计；文件 ID、随机存储名、内容和校验值不变。已发布或下架附件允许改名，平台和架构的实际变更仍要求草稿。下载响应使用最新名称生成 `Content-Disposition`，原链接和断点续传继续有效。

上传前，选择文件只进入本地待上传队列，可在原位修改完整文件名并配置平台、架构；点击上传后先保存草稿，再将选定名称用于上传，不改动用户磁盘上的原文件。已上传文件在版本编辑页原位改名，保存调用附件接口、取消还原未提交输入；成功后更新本地文件行及预览，不重载版本表单。文件管理列表继续使用独立重命名弹窗。文件名限制为最多 180 个字符，并校验同版本重名、路径、控制字符、Windows 非法字符与保留名称。

## 扩展建议

下载量增长后，优先把已发布安装包迁移到对象存储与 CDN，数据库继续管理版本和文件元数据。由于存储使用随机标识，下载路径不依赖宿主机目录，迁移时可以保持公开链接稳定。

需要多个管理员时，再引入独立身份、角色和可归属个人的审计记录。当前共享管理密钥只能标识管理员会话，不能区分具体操作人。

## 设计方向

页面采用米白背景、深色文字和墨绿色强调色。公开页面以找到项目、选择版本和下载为主要路径；后台以配置项目、整理草稿和发布为主要路径。

设计图使用浏览器渲染生成 PNG。界面字体、版本信息和中文均由真实页面排版，原始设计保留在 `design/`，正式应用位于 `web/`。
