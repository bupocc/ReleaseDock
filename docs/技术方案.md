# 软件发布中心技术方案

## 目标与边界

面向单个团队或个人自托管的软件发布需求。访客可以读取公开项目与已发布版本，下载软件；管理员通过 WebAuthn 通行密钥登录，管理站点、项目和版本。凭据可保存到 Bitwarden 官方自托管密码库，不引入访客注册、多租户或独立微服务。

## 技术选择

| 层次 | 本次选择 | 原因 |
| --- | --- | --- |
| 前端 | 原生 JavaScript 模块、HTML、CSS | 直接沿用已确认的页面，依赖少，构建和部署简单 |
| 更新日志 | Marked、DOMPurify | 后台和公开页共用 Markdown 解析，限制 HTML 标签及链接协议；依赖文件由本站提供 |
| 后端 | Node.js 24、Fastify 5 | 服务端会话、输入校验、流式文件上传与下载 |
| 管理员认证 | SimpleWebAuthn Server 14.0.1 / Browser 14.0.0 | 标准 WebAuthn 注册、签名验证与浏览器兼容处理，私钥由用户密码库或设备保管 |
| 数据库 | Node 原生 SQLite 驱动、WAL | 单机运维简单，项目与发布管理的写入规模较小 |
| 文件存储 | Docker 持久卷 | 安装包不放进数据库，更新容器不丢失文件 |
| HTTPS | 可选 Caddy 反向代理 | 自动证书申请与续期 |
| 部署 | Docker Compose | 将应用和数据目录分开，提供健康检查 |

替代方案是 Vue/React 配合独立 API 和 PostgreSQL，适合多人开发、更复杂的管理功能或多实例运行；目前会增加构建与运维成本。当前前端采用模块化组织，将来可以逐页替换。

## 公开页面与表单交互

首页默认显示更新动态，项目目录独立提供搜索、分类和排序。普通页面及后台页面地址栏统一为 `/`；`router.js` 在新文档启动时读取旧查询参数，使用 `history.replaceState` 保存 `releaseDockRoute` 并收起查询参数和锚点。刷新从当前历史条目恢复页面，不使用全站「上次页面」覆盖新标签；跨页面仍采用真实链接和完整文档导航，保留浏览器的前进、后退、新标签与未保存离开提示。登录回跳使用保存的路由信息，只允许回到同源管理页。

公开版本路径为 `/<slug>/<version>`。前后端精确保留实际版本号，避免数字版与带 v 版本共存时定位错误。`GET /api/projects/:slug/releases/:version` 与 HTML 路由使用同一公开查询，不使用会在版本改名后错误定位其他记录的前缀别名。HTML 直达路径支持刷新，隐藏、下架或不存在的版本返回 404；API 与静态资源错误不会被 HTML 回退掩盖。版本号修改后新路径生效，旧参数中按版本 ID 引用的链接会转到最新的实际版本路径。项目详情仅保留「版本发布」入口及侧栏关于信息。

目录通过一次 `GET /api/projects` 请求获得公开项目和各项目的 `latestRelease`。该字段为最新已发布版本的 ID、版本号、标题、日志片段、渠道和发布时间，另有 `notesTruncated` 标志；日志片段最多 1000 个字符，无已发布版本时为 `null`。版本按发布时间取最新，草稿与下架记录不进入摘要，不依赖全站最近 100 次发布记录去重。`latestVersion` 保留项目默认版本的含义，可能与最新一次发布的 `latestRelease.version` 不同。

`project-carousel.js` 按项目 ID 去重，以最新发布的时间排序；尚无版本的项目使用项目更新时间，并显示待发布状态。轮播展示介绍、平台、版本与详情下载链接，日志先经过 Markdown 解析和 HTML 清理，再提取纯文本并截取最多 220 字的摘要；完整代码块留在详情页。

轮播每 6 秒推进一项，普通模式使用 520 毫秒的位移与透明度过渡。悬停、组件内焦点、后台页面及手动暂停会停止计时，临时暂停条件解除后重新等待 6 秒；系统 `prefers-reduced-motion` 开启时关闭自动播放与切换动画。前后按钮、指示点、左右方向键及 Home / End 均可切换。非活动项设置 `inert` 与 `aria-hidden`，手动切换通过状态区域播报；0 或 1 项不展示播放控件。

`select-control.js` 将单选下拉增强为带 `combobox` / `listbox` 语义的控件，保留原生字段作为提交值来源，并同步禁用状态、校验信息和 `input` / `change` 事件。支持方向键、Home / End、Enter / 空格、Escape 及输入前缀定位。菜单独立挂载以避免被文件列表裁剪，按视口选择展开方向。项目支持平台以标签式复选框呈现，继续使用原生复选框的键盘与表单语义。

`platforms.js` 统一 Windows、macOS、Linux、Android、iOS、HarmonyOS、Web 的存储值、显示名称、图标和安装包识别。HarmonyOS 显示为「鸿蒙」。移动包按扩展名识别，默认使用 `universal` 架构；文件名中的明确架构标记可覆盖默认值，不把 `harmony` 中的 `arm` 子串视为 ARM64。项目保存时保留已有自定义平台。

## 数据实体

- `projects`：名称、唯一标识、介绍、官网、平台、图标、可见性。
- `releases`：所属项目、唯一版本号、标题、更新日志、渠道、发布状态及时间。
- `assets`：所属版本、展示文件名、随机存储名、平台、架构、大小、SHA-256 与下载数。
- `passkeys`：凭据 ID、公钥、计数器、RP ID、名称、设备及备份类型、创建与最近使用时间。
- `sessions`：会话令牌摘要、CSRF 令牌、绑定凭据、认证来源、最近验证时间与有效期。
- `webauthn_challenges`：单次随机挑战、用途、固定来源、RP ID、有效期以及所属浏览器、会话或初始化授权。
- `passkey_enrollments`：服务器签发的初始化或恢复票据摘要、来源与到期时间。
- `settings`：站点信息，以及不会返回前端的内部设置。
- `daily_downloads`：按 UTC 日期汇总的下载开始次数。
- `audit_log`：通行密钥绑定、改名、删除、恢复、登录、项目修改、上传、发布与下架等动作，不保存票据原文、私钥或密码库凭证。

数据库通过唯一约束保护项目标识、项目内版本号与文件名。同一个项目最多标记一个最新稳定版。

版本号是 1–100 个字符的标识，以 ASCII 字母或数字开头，后续仅允许 ASCII 字母、数字和 `. _ + -`，支持 `1.5.0.1`、`nightly` 等值，不要求三段语义版本。渠道独立使用 `stable` / `prerelease`，不从版本号后缀推断；版本展示和动态顺序依据发布记录，不能把版本标签当作可直接比较的语义版本。

## 权限规则

公开可读条件为 `项目公开 AND 版本已发布`。文件下载、版本详情和列表分别执行同一条件，避免只隐藏按钮却仍能通过 URL 访问。

管理接口的鉴权基于路由器实际匹配的路由模板，防止百分号编码改变原始 URL 后绕过前缀判断。写操作另校验 CSRF 令牌和请求来源。登录失败会限流，登录后使用 HttpOnly、SameSite=Strict Cookie；HTTPS 部署启用 Secure 属性。

不再提供文本密钥登录接口，不读取 `ADMIN_KEY` 或 `ADMIN_KEY_FILE`。数据库迁移到版本 2 时新增凭据与挑战表、会话绑定字段，并且只在此次迁移中撤销旧会话。后续正常重启保留已验证的会话与凭据。迁移在同步 SQLite 事务内执行，拒绝打开高于程序支持版本的数据库。

### 通行密钥与 Bitwarden

ReleaseDock 是 WebAuthn 依赖方。浏览器调用 Bitwarden 扩展创建或使用凭据，Bitwarden 负责自托管密码库的同步与解锁；应用不调用其密码库 API，也不接收 API Token、主密码或私钥。标准 WebAuthn 不能保证凭据一定来自某个 Bitwarden 实例，实际密码库由用户选择。

`PUBLIC_URL` 固定来源和 RP ID，正式环境要求 HTTPS 域名；无正式配置时仅允许 `http://localhost:PORT`。默认本地端口来自服务器配置，Docker 映射端口通过 Compose 明确配置，不使用来访 Host 或 Origin 推导信任域名。以 IP 地址进入公开站点时，登录页引导至配置的 localhost 地址。凭据绑定域名，更换域名后需要重新绑定。

注册要求可发现凭据 `residentKey=required`、用户验证 `userVerification=required` 和 `attestation=none`，不限制认证器为平台设备，兼容 Bitwarden、手机及硬件安全密钥。登录不下发完整允许列表，由认证器选择凭据，服务端随后核对已登记凭据 ID、固定管理员 userHandle、来源、RP ID、签名、用户在场与用户验证标志。计数由验证库处理，允许同步通行密钥正常使用零计数；非零计数不得回退，备份资格不能改变。

每次操作使用 2 分钟内有效的随机挑战，浏览器票据使用 HttpOnly、SameSite=Strict Cookie。挑战在异步验签前通过事务原子消费，失败也需要新挑战。同一响应不可重放或被两次并发请求同时采用。验签成功后，在另一同步事务中重新检查当前授权、票据期限、凭据撤销与计数器状态，随后持久化结果。不会把异步签名验证放入同步数据库事务。

### 初始化、备用凭据与恢复

首次绑定不向普通访客开放。管理员通过服务器 CLI 生成 256 位随机的一次性链接，15 分钟内有效；数据库仅存摘要，原链接只写到数据目录的私密文件。链接令牌放在 URL 片段中，前端在路由初始化前取出、立即清除并通过 POST 兑换为短期 HttpOnly 票据，不写入查询参数、浏览器历史状态或 Web Storage。成功绑定后清除全部未用初始化票据；重新签发立即作废旧链接。

站点设置可添加、改名和删除通行密钥，每个 RP 最多 20 把。管理凭据要求有效会话、同源请求、CSRF 和最近 5 分钟的通行密钥验证；过期后先再次验证。最后一把不能删除，删除某把凭据同时撤销由其建立的所有会话和待验证操作。删除当前凭据会退出登录。

全部凭据丢失时只能通过服务器 CLI 签发恢复链接。生成链接时不删除原凭据；待新凭据完整验证通过后，在同一事务中替换旧凭据并撤销全部旧会话和挑战。恢复不会触碰项目、版本或安装包。没有匿名找回、文本密钥回退或 Bitwarden 主密码登录入口。

## 版本与附件一致性

`PATCH /api/admin/releases/:id` 允许草稿、已发布和已下架版本修改版本号、标题、日志及渠道；同项目版本号唯一约束仍覆盖所有状态。已发布版本的日志不能为空。保存只更新元数据与更新时间，保留原发布状态、发布时间、版本 ID 和附件内容。发布及重新发布使用独立发布接口，下架使用独立下架接口；编辑下架版本不会恢复公开访问。

最新稳定标记仅对已发布且渠道为 `stable` 的版本有效。同一事务内交接 `is_latest`，并由唯一索引约束每个项目最多一个。发布稳定版时可指定为最新；尚无最新标记时，新发布的稳定版自动成为最新。编辑时可把另一个已发布稳定版设为最新。取消当前最新标记、将当前最新改为预发布或将其下架时，优先回退到其他已发布稳定版中发布时间最近的一项；没有候选则留空。草稿与下架版本不能通过保存元数据取得有效最新标记。

安装包先流式写入临时文件并计算校验值，完成后原子重命名，再登记数据库。超限、中断或数据库冲突会清理此次上传产生的文件。正式发布前检查文件存在；附件提交时在事务内复核所属版本存在、附件数量上限和同版本文件名唯一性。

管理员可在草稿、已发布及已下架状态增删附件、调整名称、平台与架构或替换文件。附件操作不会改变版本状态，匿名权限仍统一检查项目可见性及发布状态。删除最后一个附件后版本仍保留原状态，公开页展示无安装包提示；发布接口继续要求至少一个附件。

`PUT /api/admin/assets/:id/content` 接收一个 multipart `file`，查询参数为 `platform` 和 `arch`。先将新内容流式落盘，再在事务内复核原附件没有被删除、改名、修改元数据或被其他上传替换，随后切换存储名、大小、内容类型及 SHA-256，最后清理旧文件。下载链接、附件 ID 和累计下载数保持稳定。接收失败、文件名冲突或并发冲突都保留原文件；已有下载通过已打开的文件描述符读取，避免替换清理影响在途传输。

附件元数据使用 `PATCH /api/admin/assets/:id`，可单独提交 `filename`，也可提交平台与架构。事务内校验文件名及同版本唯一性，并更新版本时间、记录审计；文件 ID、随机存储名、内容和校验值不变。下载响应使用最新名称生成 `Content-Disposition`；内容替换后 ETag 同步更新，携带旧 If-Range 的请求会重新获取完整文件。

选择或拖入文件后自动处理上传队列。新版本缺少必填信息时暂存文件，补齐后自动保存草稿并上传；用串行任务避免重复建草稿及重复传输，失败条目保留供重试，保存和发布需等待队列完成。已上传文件在版本编辑页原位改名及替换，成功后更新文件行和预览，不重载版本表单；文件管理列表继续使用重命名弹窗。文件名限制为最多 180 个字符，并校验同版本重名、路径、控制字符、Windows 非法字符与保留名称。

## 扩展建议

下载量增长后，优先把已发布安装包迁移到对象存储与 CDN，数据库继续管理版本和文件元数据。由于存储使用随机标识，下载路径不依赖宿主机目录，迁移时可以保持公开链接稳定。

需要多个管理员时，再引入独立身份、角色和可归属个人的审计记录。当前多个通行密钥归属于同一管理员，可追踪凭据动作，但凭据名称不能作为个人身份的可靠证明。

## 设计方向

页面采用米白背景、深色文字和墨绿色强调色。公开页面以找到项目、选择版本和下载为主要路径；后台以配置项目、整理草稿和发布为主要路径。

设计图使用浏览器渲染生成 PNG。界面字体、版本信息和中文均由真实页面排版，原始设计保留在 `design/`，正式应用位于 `web/`。
