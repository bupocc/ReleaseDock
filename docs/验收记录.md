# ReleaseDock 验收记录

验收日期：2026-09-11。

## 本次完成

先完成 9 个页面的视觉设计和可点击预览，再实现真实前后端与 Docker 部署。正式应用不读取设计用示例数据，首次运行为空站点。

此前已补充更新日志解析与安装包重命名：后台编辑预览、发布预览、公开详情共享 Marked 和 DOMPurify，支持引用、链接及转义并阻断危险 HTML 和链接协议。草稿、已发布、已下架的安装包均可改名，原下载地址、存储内容与 SHA-256 保持一致。

按用户确认保留更新动态作为首页。项目目录通过「全部项目」进入，保留搜索、分类及排序。

本轮根据九张标注截图完成以下调整：

- 项目目录顶部改为最近更新项目轮播，按项目去重，每 6 秒切换并带位移动画；支持前后按钮、指示点、键盘及暂停。0 个项目显示空态，1 个项目静态展示，不创建虚构项目。移除项目标题下的英文宣传文字。
- 动态页采用紧凑标题和公告间距；登录区保留欢迎标题、密钥输入、显隐按钮和验证操作，移除多余说明，可访问标签仍保留。
- 版本号支持 `1.5.0.1`、日期、短版本及字母标签。草稿、已发布和已下架版本均可编辑版本号、标题、更新日志和渠道；保存保留发布状态和原发布时间。概览及版本列表入口统一为「编辑」。
- 安装包先进入待上传队列，允许原位修改文件名、平台及架构，再点击上传；已上传名称支持原位保存、取消及 Enter/Escape。保存一个文件不会清空其他文件或版本信息的未保存修改。
- 平台多选改为标签；项目、分类和附件等下拉使用自定义菜单。键盘、原生字段值、禁用状态以及行重绘后的焦点保持同步。
- 已发布及已下架的附件内容、平台和架构继续锁定；最新稳定版标记在事务中切换或回退，冲突时整体回滚。

## 审查与修复

补充审查复现了两处边界问题，并在交付前修复：

1. 原始 URL 前缀不能可靠代表路由匹配结果。鉴权已改用 Fastify 实际匹配的路由模板，新增编码路径的匿名读写、私有文件和 CSRF 回归。
2. 附件数量不能只在异步上传前检查。提交事务时再次核对数量，63 个附件的版本收到两次并发上传时，仅一份成功，最终数量为 64，拒绝的临时文件被清理。

此前独立审查复核了改名事务、已发布附件的元数据边界和 Markdown 清理流程。两个前端依赖模块使用精确白名单路由提供，不公开整个依赖目录。

本轮回归补上了动态附件行重绘后的键盘焦点恢复，并扩大平台列以完整显示 Windows。自定义下拉菜单在页面根部展开，避免被表格滚动容器裁剪；表单重置使用统一监听，避免反复重绘时累积监听器。另验证超过 100 条全站更新时，目录仍能找到各项目自己的最近已发布版本，摘要最多传输 1000 个字符。

## 部署状态与范围

正式应用已在本机 Docker 运行，使用命名数据卷。未提供云服务器连接信息或实际域名，因此没有执行远程部署、DNS 配置或证书申请。

本次沿用已验证的公开镜像源构建，生产依赖按锁文件安装；默认部署文件仍支持官方镜像。未修改系统 Docker 镜像源配置。

浏览器验收使用 Chrome，包含 390px 手机视口；尚未进行公网负载、真实 2 GB 大文件或多浏览器兼容性专项测试。程序当前定位为单实例自托管应用。
